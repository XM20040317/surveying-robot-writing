# 测绘项目报告书写作

把一份测绘项目报告写到"评审挑不出硬伤"，靠的不是文采，是**可核验**。本技能提供骨架、表格模板、自检清单和退件原因库，不提供任何标准条款原文和限差数字。

## 这个技能管什么 / 不管什么

| 管 | 不管 |
|---|---|
| 技术设计书、技术总结、结题报告、验收报告、质检报告的章节骨架 | 具体测绘生产作业（选点、观测、平差、调绘的操作步骤） |
| 把规范指标翻译成"可核验的表格" | 代替注册测绘师或质检机构做技术裁定 |
| 送审前自检、退件原因排查、附件清单核对 | 编造标准条款、限差数值、验收意见、专家名单 |
| 项目申报书中"技术方案"部分的写法 | 学术论文、期刊投稿（用论文写作技能） |

三条底线，任何一条破了，报告就白写：

1. **不编造**：标准条款原文、限差数值、验收结论、专家意见，一律不虚构。
2. **可追溯**：正文每个数字都能指回某张表、某次检查记录、某份附件。
3. **不越权**：技能给结构和写法，技术结论由项目负责人签字、质检机构盖章。

## 先问四件事

四个问题没答完，不要动笔。答错任何一个，骨架就要重搭。

| # | 问什么 | 常见答案 | 决定了什么 |
|---|---|---|---|
| 1 | 项目类型 | 技术设计 / 技术总结 / 结题 / 验收 / 质检 | 章节骨架、时态（将做/已做）、是否要写"未完成事项" |
| 2 | 成果类型 | DLG / DEM / DOM / 点云 / 实景三维 / 变形监测数据 | 精度指标从哪本规范来、质检抽什么、附件是什么形态 |
| 3 | 依据的标准体系 | 国家标准 / 测绘行业标准 / 地方标准 / 合同技术条款 | 指标来源、引用格式、冲突时的优先级 |
| 4 | 交付对象 | 甲方 / 评审专家 / 行业主管部门 | 详略取舍、口径、是否附评审意见与整改说明 |

补充确认（问不到就按保守写法处理）：

- 成果是否涉密、涉密等级、能否公开出版或上网。
- 项目是否分期，本次报告覆盖哪一期、哪些内容不在范围内。
- 有没有上一版报告或评审意见，需要"逐条回应"而不是重写。

## 三类报告的骨架对照

同一件事，三种时态。设计书说"将怎么做"，总结说"实际怎么做、结果如何"，结题说"承诺的都做到了，证据在这"。

| 章节 | 技术设计书 | 技术总结 | 结题报告 |
|---|---|---|---|
| 封面与扉页 | 项目名称、编写/审核/批准、日期、单位 | 同左，加"数据生产起止时间" | 同左，加项目编号与合同号 |
| 概述 | 任务来源、目标、范围、工作量预估 | 任务来源、目标、范围、实际完成工作量 | 立项背景、任务书下达、考核目标 |
| 已有资料 | 资料清单、可用性、精度与现势性评价 | 实际使用资料、与设计的差异 | 简写，重点写资源投入 |
| 技术依据 | 标准全号+年号+合同+技术文件 | 同左，只列实际执行的 | 同左，只列影响考核指标的 |
| 技术路线 | 流程图、工序说明、仪器设备 | 实际路线、变更及原因 | 技术难点与创新点（须有佐证） |
| 精度与质量 | 设计指标、允许中误差、误差分配 | 实测精度统计表、合格率 | 考核指标完成情况对照表 |
| 组织实施 | 机构、人员、设备、进度计划 | 实际投入、实际进度、延期说明 | 经费执行、人员投入（如需要） |
| 质量控制 | 两级检查一级验收的设计 | 检查记录、问题处理、返工情况 | 质检结论、验收结论 |
| 成果与附件 | 拟提交成果清单 | 实际提交清单+存放位置 | 成果清单+佐证材料索引 |
| 结论 | 预期成果（不写"将达到国内领先"） | 结论与建议、遗留问题 | 目标达成度、后续工作建议 |

### 常见场景对应哪种报告

| 用户这么说 | 实际要写 | 最容易搞错的地方 |
|---|---|---|
| "下周要投标" | 技术方案（按设计书裁剪） | 写成产品介绍，指标没有出处 |
| "活干完了要交差" | 技术总结+成果清单 | 只写过程，不写精度统计 |
| "要验收了" | 验收报告+质检报告 | 自评质量等级、代写验收意见 |
| "项目要结题" | 结题报告+考核指标对照表 | 改写考核指标、缺佐证材料 |
| "甲方要一份情况说明" | 技术说明（简报式） | 套全套骨架，重点被淹没 |

## 硬规则

八条，逐条对照，缺一条就退回重写。

1. **指标必须可核验**：写"平面中误差不大于限差"，就要给出检查项、样本数、实测中误差、判定结论。写不出检查方法的指标，等于没写。
2. **标准必须写全号与年号，并注明现行**：首次出现处写 `标准号—年号 标准名称（以现行有效版本为准）`。年号不确认就去查，不要空着、不要沿用已废止版本、不要凭记忆写。
3. **不得把"完成"写成"优秀"**：完成是事实判断，优秀是等级判断。等级只能由质检或验收机构按标准评定，报告正文只能引用其结论。
4. **数据与结论一一对应**：结论段每个形容词（稳定、可靠、满足要求）前面必须有一张表或一组数据支撑，否则删掉。
5. **附录清单齐全**：正文提到的每份附件，附录里都要有编号、名称、页数；附录里有的，正文必须引用。
6. **不编造验收意见**：验收意见、专家名单、评审结论只能来自会议记录或书面文件；未发生的写"拟于×月组织验收"。
7. **单位与有效数字统一**：全文一套单位（m / km / mm / 中误差 mm），有效数字位数与仪器精度、限差位数匹配，全文一致。
8. **涉密与脱敏**：涉密成果按保密规定处理，报告中不出现敏感坐标、可反推的起算数据、敏感点位照片；对外发布另做脱敏版。

## 工作流

五步，前一步不完成不进下一步。

| 步骤 | 做什么 | 产出 | 卡点 |
|---|---|---|---|
| 1 锁定依据 | 把合同、任务书、规范、上版报告收齐，列出"指标—出处"对照表 | 依据清单 | 找不到出处的指标，先问甲方，不要自己定 |
| 2 搭骨架 | 按项目类型选骨架，先写目录到三级标题 | 目录+每章一句话主旨 | 目录里出现"其他""相关""有关"就删 |
| 3 填指标 | 先填表（精度、工作量、进度、成果），再写解释表的文字 | 全套表格 | 表格空着的地方，就是还没想清楚的地方 |
| 4 自检 | 过"硬规则 8 条"+"自检 20 条"+"一页纸自检" | 自检记录 | 自检发现的问题要留痕，不要静默改掉 |
| 5 交付 | 转 Word、编图表号、补页眉页脚、核附件清单 | 送审稿+附件包 | 转版后逐页看一遍，表格和公式最容易崩 |

## 输出规范

**Markdown → Word**

- 用标题层级（`#`/`##`/`###`）表达结构，不要用加粗假标题，否则转 Word 后生成不了导航目录。
- 表格一律用管道表，不用截图表格；合并单元格在 Markdown 里做不了，转 Word 后再处理。
- 公式用纯文本或代码块写清符号含义，转 Word 后人工替换为公式对象。
- 图片用 `![图 3-1 技术路线图](figs/fig-3-1.png)`，路径写成相对路径，随稿一起打包。

**图表编号**

- 规则：`图 章-序`、`表 章-序`，如"图 3-1""表 4-2"，全文连续，不跳号。
- 图题在图下居中，表题在表上居中；单位写在表头（如"中误差/mm"），不重复写进每个单元格。
- 正文先引用后出现："技术路线见图 3-1"，不允许图先出现、正文后面才提。

**页眉页脚**

- 页眉：项目名称（左）+ 报告类型（右）；页脚："第 X 页 共 Y 页"。
- 正文从第 1 页起编，封面、扉页、目录不编页码或改用罗马数字。
- 送审稿在封面或页眉标注"送审稿"及日期，避免与最终版混用。

**附件清单**

- 附件单独编页，编号 `附件 1`、`附件 2`，与正文引用编号完全一致。
- 每份附件写清：名称、份数或页数、形式（纸质/电子）、存放位置或载体。
- 常见附件：合同或任务书、仪器检定证书、检查记录表、精度统计表、质检报告、验收意见、软件测评或登记证明。

**文件命名与版本**

- 命名：`项目简称_报告类型_版本_日期`，如 `××测区_技术总结_v3_20250630`。
- 版本只增不改：v1 评审稿、v2 修改稿、v3 送审稿、v4 最终稿；每次升版附一页修改说明，逐条对应评审意见。
- 最终稿单独存放，不与过程稿混在同一目录；对外只发 PDF，可编辑稿留在项目内部。
