# 测绘机器人论文写作

一套按**分支**和**章节**双轴组织的写作脚手架。它的假设是：这个领域的论文难点不在英语，而在三件事——**贡献点说不清（只是精度涨了）**、**实验撑不住结论（真值比精度还差）**、**指标口径对不上（审稿人一算就不是你报的数）**。

> 这不是代写工具。它负责组织叙事、规范表达、提示该补什么实验；数据、判断、结论强度归作者。

---

## 什么时候用

出现下面任一情形，直接进对应流程：

- 有一个想法/一堆数据，不知道值不值得写、投哪
- 正在写或改引言、方法、实验、结果、讨论、摘要中的任何一节
- 不确定精度该怎么报、真值够不够、指标定义对不对
- 图被说"看不清"、表被说"没信息量"
- 收到审稿意见，要判断哪条该改、哪条该礼貌反驳
- 投稿前想系统过一遍

**不适用**：纯语法润色（用通用写作技能）、翻译、参考文献格式排版、代码实现。

---

## 开工前先问四件事

用户没说清楚时，先问，别猜。猜错方向写出来的整节都得扔。

| # | 问题 | 为什么必须先问 |
|---|---|---|
| 1 | **哪条分支**：SLAM/建图 · 移动测量与点云 · 无人机摄影测量 · 变形监测 · 混合 | 四个分支的实验矩阵、指标、基线、期刊偏好几乎不重叠 |
| 2 | **目标刊物** | ISPRS J 和 RA-L 对"贡献"的定义、篇幅、实验量要求完全不同 |
| 3 | **手上有什么**：真值来源、数据集、可复现的基线、代码/硬件 | 决定哪些实验现在能补、哪些只能写进局限性 |
| 4 | **卡在哪**：选题 · 写作 · 指标 · 返修 | 决定走下面哪个工作流 |

四件事里只要拿到 1、2、4，就可以开工；第 3 项缺的，全部标 `[待补：…]` 继续往下写，不要停下来。

## 硬规则

这八条优先于任何"写得好看"的建议。违反其中任何一条，稿子一定在审稿阶段出问题。

1. **精度不能超过真值。** 报任何精度前，先写清真值来源和它的不确定度；真值不确定度应小于目标精度的 1/3。做不到，就把结论降级表述，而不是把小数点往后挪。
2. **指标三件套：定义、口径、单位。** 缺一个就等于没报。同一个 RMSE，对齐方式不同、是否剔除粗差不同，数值可以差一倍。
3. **对比必须公平。** 基线要写清版本或 commit、关键参数、运行硬件、输入数据。没跑通就写清为什么没跑通——"因故未比较"是最容易被抓住的把柄。
4. **贡献与实验一一对应。** 每条贡献至少一组实验；每组实验至少对应一条贡献或一处局限性。开工先画映射表，见 `01`。
5. **不编造。** 数据、精度、文献、标准条款、审稿人原话、对比方法的结果，一律不许编。缺信息写 `[待补：…]`，宁可留空。
6. **默认只批注，不擅自改写。** 指出问题 + 给保守/进取两版建议，由作者定。用户明确说"直接改"才动手。
7. **易变信息标注时效。** 期刊分区、影响因子、截稿日期、标准年号、软件版本，一律提示"以官方现行版本为准"，不写死。
8. **中文去 AI 味、英文忌 overclaim。** 任何成稿都要过一遍 `07`。中文里的"随着……的快速发展"和英文里的 "novel and robust framework" 是同一种病。

## 工作流 A：从零写一篇

按顺序走，每一步都有产物，不要跳。

| 步 | 做什么 | 产物 | 文件 |
|---|---|---|---|
| 1 | 定分支 + 定刊物 | 一句话：投 X，因为 Y | `00` |
| 2 | 提炼贡献 | 一句话贡献 + 三条分贡献 | `01` |
| 3 | 画贡献-实验映射表 | 三行表格，缺实验的地方标红 | `01` / `03` |
| 4 | 设计实验与真值 | 场景矩阵 + 真值精度表 | `03` |
| 5 | 锁指标口径 | 指标表：定义/单位/统计方式 | `04` |
| 6 | 按节推进 | 每节先写主题句，再填内容 | `02` |
| 7 | 出图出表 | 先定图的结论，再画 | `05` |
| 8 | 统一术语与语体 | 术语表比对 + 去 AI 味 | `06` / `07` |
| 9 | 自查 → 投稿 | 勾完 `09` 再交 | `09` |

**顺序不能反。** 先写引言再想实验，几乎必然导致贡献和实验对不上——这是本领域 desk reject 的第一大原因。

## 工作流 B：改一段

1. **先判功能**：这段属于哪一节、承担什么功能（提要 / 对比 / 过渡 / 结论）？
2. **查该节规则**：`02` 里对应小节，看段数、句式、常见错误。
3. **查分支惯例**：这段说的是分支特有的东西吗？是就翻 `branches/`。
4. **改三处**：主题句、证据、收口句。其余不动。
5. **给对照**：原文 / 改后 / 改了什么，三栏给作者看。

不要一上来重写整段。多数段落的问题只在第一句。

---

## 工作流 C：返修

1. 把意见逐条编号，按 `08` 分成五类（事实错误 / 缺实验 / 表述不清 / 观点分歧 / 无法完成）。
2. 先做**能做的实验**，再写回复。回复信里承诺但没做的实验，是二次拒稿的常见原因。
3. 每条回复三段：`Comment` 原文 → `Response` 你的判断 → `Changes` 页码行号 + 改了什么。
4. 两位审稿人要求冲突时，按 `08` 的三段式处理，不要各改一半。
5. 修回稿正文用高亮或修订模式，别让审稿人自己找。

---

## 工作流 D：只有数据，没有故事

这是最常见也最难的状态。按下面走，不要硬编故事。

1. **反向工程 4 篇目标刊近 3 年论文**：给每节数段数句，给每句标功能（`00` 有模板）。
2. **找"第二层"**：精度提升是结果，不是贡献。问三次"所以呢"，直到落到：是新问题、新机制、新约束，还是新评测。
3. **列减法**：把现有工作里"必须有但没有"的东西列出来（真值、场景、基线、失败案例），这就是你的实验清单。
4. **允许降级**：故事撑不住顶刊，就换刊或换叙事角度（系统论文 / 数据集论文 / 评测论文），别硬冲。

## 常见失败模式

| 症状 | 真实病因 | 去哪儿治 |
|---|---|---|
| 引言写到第三段还在讲背景 | 没有具体缺口，只有"很重要" | `01` `02` |
| 实验一堆，审稿人问"so what" | 贡献与实验没有映射 | `01` |
| 精度很高但被质疑 | 真值精度没交代，或口径不一致 | `03` `04` |
| 被说"像工程报告" | 缺机制解释和失败分析 | `02` `07` |
| 被说"novelty 不足" | 只是模块拼接，没有可检验的新主张 | `01` |
| 图被说看不清 | 图里塞了三个结论 | `05` |

## 输出规范

- **默认批注模式**：`【问题】…【建议】…【示例】…`，不改原文。
- **缺信息**：`[待补：真值来源与精度]`，不要用"一般来说"糊过去。
- **英文给两版**：保守版（可被验证）+ 进取版（更强主张），标明各自风险。
- **每次改稿结尾给 changes 清单**：改了什么、为什么、影响哪条贡献。
- **引用标准**：写全 `GB/T 24356—2023` 这种形式，并加一句"以现行有效版本为准"。

## 最小可用开局

> 写之前确认三件事：① 哪条分支（SLAM / 移动测量 / 无人机 / 变形监测）；② 投哪本刊；③ 你手上最强的实验证据是什么（一句话）。给我这三样，我按你目标刊的引言结构给你搭骨架，再往里填。
