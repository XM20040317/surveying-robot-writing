# 去 AI 味与学术语体

AI 味通常不是某一个词造成的，而是三种习惯叠加：用背景代替问题、用形容词代替证据、用总结代替边界。去 AI 味也不是把句子改短，而是让每个句子承担明确功能：提出主张、给出机制、报告证据、限定范围。下面的病句与改写均为示例，不对应任何真实论文或数据。

## 中文 AI 味的 20 个信号

| 信号 | 典型病句 | 改法（正确示例） | 为什么 |
|---|---|---|---|
| 万能开头 | “随着测绘机器人技术的快速发展，复杂环境下的建图问题受到广泛关注。” | “在 GNSS 拒止的长走廊中，LiDAR 点云沿巷道方向约束不足，位姿估计会持续漂移。” | 第一句就给出具体失效条件，而不是时代背景。 |
| 空泛背景 | “近年来，SLAM 技术取得了长足进步。” | “现有 LiDAR SLAM 在几何退化场景中仍会失效，本文关注退化检测与恢复。” | “进步”不可检验；改成可观测的问题。 |
| 三段式排比 | “该系统既要保证精度，又要保证效率，还要保证鲁棒性。” | “系统需在嵌入式平台上输出位姿；精度与鲁棒性的取舍见第 4 节。” | 排比把约束混在一起，没有优先级与指标。 |
| “不仅……而且……” | “该方法不仅提高了定位精度，而且增强了系统鲁棒性。” | “该方法加入回环约束；动态场景中的跟踪稳定性见 4.3 节。” | 并列连接词掩盖了两类不同证据。 |
| 形容词堆叠 | “提出一种高效、精准、鲁棒的配准方法。” | “提出一种基于……的配准方法，耗时与配准误差分别见表 2、表 3。” | 三个形容词都不可核验，表号才能定位证据。 |
| 每段结尾强行总结 | “由此可见，该方法具有显著优势。” | 删去；若必须收束，写“在本文测试的室内场景中，该方法完成率高于基线”。 | 总结句不增加信息，且常超出本段证据。 |
| “综上所述” | “综上所述，本文方法性能优越。” | “在本文测试场景中，本文方法的 RMSE 低于基线；跨场景泛化仍未验证。” | 套话替代了分点证据与边界。 |
| 空洞的“具有重要意义” | “该研究对推动测绘机器人发展具有重要意义。” | “该研究给出的退化检测指标可用于触发重定位。” | “意义”没有作用对象与机制。 |
| 过度使用“显著” | “精度显著提高，鲁棒性显著增强。” | “RMSE 降低，差异经配对检验（p 值见表 3）；鲁棒性仅在……扰动下测试。” | “显著”有统计含义，不能当程度副词。 |
| 被动句堆叠 | “数据被采集后，被预处理，并被用于训练，模型被验证。” | “我们采集数据，完成预处理后训练模型，并在独立测区验证。” | 被动掩盖执行者，句子失去责任主体。 |
| “本文旨在……” | “本文旨在研究一种新的 SLAM 方法。” | “本文提出一种……的 SLAM 方法，并在……上评估。” | “旨在”只表态，不说明做了什么。 |
| 同义反复 | “对点云数据进行去噪处理分析研究。” | “对点云去噪。” | “进行、处理、分析、研究”叠用，动词被名词化。 |
| 量词缺失 | “大量实验表明，一些方法效果更好。” | “在全部测试序列上，本文方法与所选基线比较，结果见表 3。” | “大量、一些”没有边界，读者无法判断证据量。 |
| 数据无出处 | “实验表明，该方法精度更高。” | “在自建数据集上，按第 4.2 节指标评估，结果见表 3。” | 结论没有数据、指标、表号或文献。 |
| 连接词滥用 | “此外，同时，然而，该方法还具有良好的实时性。” | “该方法在嵌入式平台上的时延见 4.4 节。” | 连接词不建立逻辑，只制造流畅感。 |
| 编号化表达 | “首先，采集数据；其次，训练模型；最后，验证方法。” | “数据采集、模型训练与独立测区验证构成一条流程，各步输入输出见图 2。” | “首先、其次、最后”只标记顺序，不说明因果与依赖。 |
| 主语丢失 | “通过实验验证了方法的有效性。” | “第 5 节在两类退化场景中验证该方法，指标为……” | 谁验证、验证什么、在什么条件下均缺失。 |
| 绝对化 | “该方法有效解决了复杂环境下的建图问题。” | “该方法在……场景中降低了漂移；在……场景中仍会失效。” | “有效解决”把局部结果写成普遍结论。 |
| 英文直译 | “在真实世界环境中进行了广泛实验。” | “在校园与地下车库场景中测试。” | “真实世界环境、广泛”是直译式空话，换成场景名。 |
| 结论复述摘要 | “本文提出……实验表明……未来将……”（与摘要逐字重复） | “本文方法的主要限制是……；下一步用……数据检验……” | 结论应新增边界与下一步，而不是复制摘要。 |

## 英文 overclaim 清单

原则：动词强度由证据强度决定；没有相同数据划分与统计检验，不写全局优于。

| 弱化前 | 弱化后 | 适用场景 |
|---|---|---|
| `prove` | `support` / `provide evidence for` | 实验不能排除替代解释时；实证论文少用 prove。 |
| `demonstrate` | `show` / `indicate` | 单一数据集、单场景或机制未排除时；demonstrate 需要更强证据。 |
| `novel` | `new` / `different from existing ...` | novelty 未经系统检索时；不要用 novel 代替贡献。 |
| `first` | `to our knowledge, the first ...` / `among the first` | 只有完成检索并限定范围时才用；否则删去。 |
| `significant` | `substantial` / `measurable` / `statistically significant`（须给检验） | 统计显著必须给检验；程度显著要给幅度。 |
| `outperform` | `performs comparably to` / `improves ... on ...` | 只在同一数据划分与评测协议下；避免写成全局优于。 |
| `robust` | `stable under ...` / `retains performance under ...` | 只有测试了扰动、噪声或缺失时才用；说明类型与强度。 |
| `real-time` | `meets the ... ms latency` / `runs at ... Hz on ...` | 必须给硬件、时延、频率；online 不等于 real-time。 |
| `state-of-the-art` | `competitive with strong baselines` / `comparable to ...` | 未全面复现所有 SOTA 时；避免“最先进”。 |
| `solve` | `mitigate` / `address` / `improve` | 开放问题只能解决子问题；写清设定。 |
| `perfect` | `near-perfect` / `low-error` | 存在失败案例时；同时给失败条件。 |
| `always` | `consistently` / `in most tested cases` | 有例外时；不要做全称量化。 |
| `substantially` | `by a margin of ...` / 具体指标 | 没有效应量时；substantially 不可核验。 |
| `comprehensive` | `extensive` / `across N settings` | 只测少量场景时；comprehensive 是强主张。 |
| `general` | `transfers to ...` / `works across ...` | 未做跨域测试时；general 需要外部验证。 |

```text
Before: The proposed method proves that ... and significantly outperforms all state-of-the-art methods.
After: On the tested sequences, the proposed method reduced ... relative to the strongest baseline; the difference was significant under a paired test (see Table ...).
```

## 模糊限制语强度表

| 强度 | 表达 | 允许使用的条件 | 误用 → 改写 |
|---|---|---|---|
| 最强 | `demonstrates` / `establishes` | 有对照、在多个数据或场景重复、主要替代解释被排除，并报告不确定度。 | 单次实验写 demonstrates → 改为 indicates。 |
| 强 | `shows` | 有直接对照与可复核数据，但机制尚未完全排除。 | 机制句写 shows → 改为 suggests。 |
| 中强 | `indicates` | 结果与假设一致，但证据不具排他性。 | 因果句写 indicates → 改为 is consistent with。 |
| 中 | `suggests` | 探索性结果、相关性或案例研究。 | 全称结论写 suggests ... all → 改为 may transfer to similar ...。 |
| 弱 | `appears to` | 观察性趋势、测量噪声较大、结果尚不稳定。 | 已有明确结果却写 appears to → 改为 shows。 |
| 最弱 | `may` / `might` | 可能性、机制推测或未来工作。 | 已测量事实写 may → 改为现在时或过去时。 |

最强词只用于：有对照实验、结果在独立数据或场景重复、主要替代解释被排除、并报告不确定度。达不到其中任何一条，就降一级。降级不是谦虚，而是让动词与证据强度匹配；也不要用 `may` 描述自己已经测到的结果。

```text
The results demonstrate ...
The results show ...
The results indicate ...
The results suggest ...
The results appear to ...
The results may ...
```

## 时态与语态纪律

不同期刊与学科存在差异，以目标刊论文为准；核心是同一功能保持一致，不要在同一段里来回切换。

| 章节 | 主时态 | 例子 | 说明 |
|---|---|---|---|
| 标题 | 一般现在时或名词短语 | `A LiDAR-inertial ... for ...` | 标题不叙事，不用过去时。 |
| 摘要—贡献 | 一般现在时 | `We present ...` | 与全文贡献表述一致。 |
| 摘要—实验 | 一般过去时 | `We evaluated ...` | 描述已完成的具体操作。 |
| 引言—背景 | 一般现在时 | `Mobile mapping systems provide ...` | 已成立的知识。 |
| 引言—前人工作 | 现在完成时或一般过去时 | `Prior work has shown ...` / `X et al. proposed ...` | 积累用完成时，单次研究用过去时。 |
| 方法 | 一般现在时 | `The front end estimates ...` | 描述算法机制。 |
| 实现 | 一般过去时 | `We implemented ...` | 已完成的工程选择。 |
| 数据与设置 | 一般过去时或一般现在时 | `We collected ...` / `The dataset contains ...` | 动作在过去，数据属性用现在时。 |
| 结果 | 一般过去时 | `The RMSE decreased ...` | 报告观察值；解释时转现在时。 |
| 讨论 | 一般现在时或情态动词 | `These results suggest ...` | 解释、边界与推论。 |
| 结论 | 现在完成时或一般现在时 | `We have shown ...` | 贡献与结论；不引入新数据。 |
| 图表标题 | 一般现在时 | `Figure 3 shows ...` | 不用 `showed`。 |
| 未来工作 | 一般将来时或情态动词 | `Future work will ...` | 不用现在完成时。 |

```text
Introduction: Mobile mapping systems provide ...
Method: The front end estimates ...
Results: The RMSE decreased ...
Discussion: These results suggest ...
```

### 语态

| 场景 | 更常用 | 说明 |
|---|---|---|
| 提出贡献 | `We propose ...` | 主动明确责任；`A method is proposed` 也可，但不要整节被动。 |
| 实验操作 | `We collected ...` 或 `Data were collected ...` | 主动交代执行者；被动时确保动作对象清楚。 |
| 机制描述 | `The filter estimates ...` | 无生命主语可以主动，不必改成被动。 |
| 失败与限制 | `We did not evaluate ...` | 主动承认边界，比 `It was not evaluated` 更清楚。 |

## 段落节奏

一段只回答一个问题。主题句放在第一句，后文给机制或证据，末句给边界；背景最多一句，且必须服务于问题。段末不重复段首；如果删掉最后一句信息不变，就删。

**AI 味段落（示例，约 120 字）**

> 随着测绘机器人技术的快速发展，复杂环境下的高精度建图受到了广泛关注。本文旨在研究一种高效、精准、鲁棒的 SLAM 方法。该方法不仅提高了定位精度，而且增强了系统鲁棒性。实验表明，该方法具有显著优势。综上所述，本文方法具有重要的理论意义和应用价值。

**改写后（示例，约 120 字）**

> 针对长走廊中 LiDAR 几何退化导致的漂移，本文在前端加入退化检测，并在检测触发时转入重定位。实验在校园走廊与地下车库两类场景进行，与所选基线比较；评价指标为轨迹 RMSE 与重定位成功率。结果显示，退化检测减少了长走廊段的漂移，但在地下车库的弱纹理区域仍出现跟踪失败。

### 逐句标注

| 原句 | 问题 | 改写对应 | 改了什么 |
|---|---|---|---|
| 随着……受到广泛关注。 | 万能开头；没有具体问题。 | 针对长走廊……持续漂移。 | 用可观测的失效场景替换时代背景。 |
| 本文旨在研究……高效、精准、鲁棒…… | 只表态；形容词堆叠。 | 本文在前端加入……转入重定位。 | 把“研究”换成动作，删掉三个不可核验的形容词。 |
| 不仅……而且…… | 并列空泛；两项主张都没有证据。 | 实验在……比较；指标为…… | 把主张拆成实验设计与评价指标。 |
| 实验表明……显著优势。 | 无数据、无出处；“显著”滥用。 | 结果显示……仍出现跟踪失败。 | 给对照、指标与失败边界，删“显著优势”。 |
| 综上所述……重要意义。 | 套话收尾；“意义”没有机制。 | 删去总结，保留末句限制。 | 用具体限制替代意义宣示。 |

## 数字与单位的写法

数字与单位以目标期刊作者指南和 SI 为准；下表给常见做法，核心是全文统一。

| 项目 | 错误写法（示例） | 正确写法（示例） | 说明 |
|---|---|---|---|
| 有效数字 | `0.123456 m` | `0.123 m` | 位数由仪器精度与不确定度决定，不保留无意义数字。 |
| 单位空格 | `10m` | `10 m` | 数值与单位符号之间空一格；`%` 按目标刊模板并全文统一，`°` 紧贴数值。 |
| ± | `10±0.5m` | `10.0 ± 0.5 m` | 单位只写一次；中心值与不确定度位数对齐。 |
| 百分数 | `提高了 5%`（未说明绝对或相对） | `提高了 5 个百分点` 或 `相对提高 5%（以……为基准）` | 区分绝对变化与相对变化。 |
| 范围 | `10-20 m` | `10–20 m` 或 `10 m 至 20 m` | 数值范围用 en dash；负号用 minus，不用 hyphen。 |
| 科学计数 | `1x10^3` | `1 × 10^3` | 乘号与指数格式统一；有效数字明确。 |
| 前导零 | `.5 m` | `0.5 m` | 不省略小数点前的零。 |
| 千分位 | `1,000 m` 与 `1 000 m` 混用 | 按目标刊统一一种 | 英文常用逗号，SI 风格常用空格；不要混用。 |
| 频率 | `10Hz` | `10 Hz` | 单位符号大小写敏感；`Hz` 不是 `HZ`。 |
| 角度 | `30 °` | `30°` | 度符号紧贴数值；分秒写 `30°15′`。 |
| 坐标 | `(1,2,3)m` | `(1.00, 2.00, 3.00) m` | 单位在括号外，小数位统一。 |
| 统计量 | `1.2±0.3` | `1.2 ± 0.3 (mean ± SD, n = N)` | 注明 SD 或 SE、样本量；不要只写 ±。 |
| 单位大小写 | `KM`、`hz` | `km`、`Hz` | 单位符号不是普通缩写，不能随意大写。 |
| 中文与英文 | 中文正文写 `0.5 米`，图表写 `0.5 m` | 全文统一；图表优先单位符号 | 中文叙述可用汉字单位，但同一量保持一种写法。 |
| 百分位 | `95% percentile` | `95th percentile` | 百分位不是百分数。 |

## 自查清单

- [ ] 每段首句是主张句，不是“随着……”。
- [ ] 删掉至少一半“显著、有效、优异、重要”，每个保留的词都有证据对应。
- [ ] 每个强结论都能指到表号、图号或统计量。
- [ ] 英文动词强度与证据匹配，没有用 `demonstrate` 包装单次实验。
- [ ] 全文术语与缩写首次定义一致，同一概念只有一种译法。
- [ ] 时态按章节统一；结果段没有用现在时叙述已完成的实验。
- [ ] 数字有效位数、单位空格、±、%、范围写法全文一致。
- [ ] 每个段末都没有强行“综上所述”，结论段没有复制摘要。
- [ ] 局限性与失败案例具体到场景，不写“未来将进一步研究”。
- [ ] 朗读一遍，删去不增加信息的连接词和形容词。
